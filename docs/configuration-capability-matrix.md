## Value-source contract

ValueSource is a closed union: `{value: JSON}`, `{path: [...]}`, or `{provider: "binding.path"}`. `{binding: "binding.path"}` is a separate executable/native-object reference used only by fields that accept it. Paths start at `args`, `kwargs`, `result`, `error`, or `context`; Python `input` selects the first bound user parameter (receiver excluded and signature-bound); TypeScript `input` selects the first supplied positional argument. Python `params` selects a bound formal name, including keyword-only values; TypeScript `params` selects a positional alias declared by `parameter_names`. Paths are checked against the field's pre/post phase. Providers receive one invocation object with `args`, `kwargs`, `result`, `error`, `context`, and `agent_name`. TypeScript supplies an empty `kwargs` object because its checkpoint seam is positional. Missing selected values fail; config never evaluates code, imports modules, traverses accessors, or guesses.

## Capability rule

Each config property must affect a documented request, snapshot, decision, installation, or lifecycle behavior. Unknown properties fail schema validation. Known language-specific fields fail locally before identity GETs if that SDK cannot consume them. Literal state and selected fields are JSON-snapshotted. Post-mapping failures never replay an application action.

## Why publication uses an existing-agent endpoint

Startup is GET-only unless `schemas.publish` is explicitly true. Registration after a successful GET could recreate an identity deleted between the requests. The PUT endpoint locks the existing namespace-scoped row, checks the agent update authority and API-key agent scope, then adds compatible step schemas without inserting an agent or replacing Rules, evaluators, agent metadata, or unmentioned Steps. Existing input/output schema values must match. Explicit description/metadata fields may be updated; omitted values remain unchanged.

Publication is atomic per agent. A directory with multiple agents does not form one remote transaction: if a later agent fails to publish, earlier remote publications remain. Local function and native-adapter installation occurs only after all requested publications succeed and rolls back as one local transaction.

## Configuration UX proof

The current [configuration UX TypeScript example](../examples/instrumentation/configuration-ux/typescript/) loads one JSON and one YAML config through one public `configure()` call. Its test uses the public `HTTPClient` seam with a strict control-contract transport double and exercises ordinary finish and natural stream finish. Python has the equivalent shared selectors and its own runtime coverage. These examples and tests do not amend the historical configuration-parity trials. See the [configuration selector contract](configuration-ux.md) for the exact language-specific limits.
